# 3Dファイル形式のセキュリティリスク

このドキュメントでは、Blenderが対応する3Dファイル形式のセキュリティリスクを分析し、必要なスキャン機能について整理します。

## 概要

3Dファイルには、単純なジオメトリデータだけでなく、スクリプトやメタデータが含まれる場合があります。これらは以下のセキュリティリスクをもたらす可能性があります：

1. **コード実行リスク** - 埋め込みスクリプトによる任意コード実行
2. **プライバシーリスク** - メタデータに含まれる個人情報の漏洩
3. **パストラバーサル** - 外部参照パスによる意図しないファイルアクセス

## リスク分類

### リスクレベル定義

| レベル | 説明 |
|--------|------|
| **高** | スクリプト実行機能があり、任意コード実行の可能性がある |
| **中** | 限定的なスクリプト機能、またはプライバシー情報漏洩の可能性がある |
| **低** | データのみだが、外部参照やメタデータに注意が必要 |
| **最低** | 純粋なジオメトリデータのみ、検査不要 |

---

## 高リスク形式

### Blender (.blend)

**リスクレベル: 高**

Blenderネイティブ形式。最も多機能であり、最も高いセキュリティリスクを持つ。

#### コード実行リスク

| 埋め込み場所 | 説明 | 自動実行 |
|--------------|------|:--------:|
| テキストブロック | Pythonスクリプトを保存可能 | 条件付き |
| ドライバー式 | プロパティに数式/Python式を設定 | **自動** |
| App Handlers | ファイル読み込み時のフック | **自動** |
| Geometry Nodes | Script ノードでPython実行 | **自動** |
| アドオン参照 | 外部アドオンへの依存 | 条件付き |

#### 検出すべきパターン

**マルウェアパターン（エラーレベル）**
- `os.system`, `os.popen` - シェルコマンド実行
- `subprocess` - プロセス生成
- `exec(`, `eval(` - 動的コード実行
- `socket.` - ネットワーク通信
- `requests.`, `urllib.` - HTTP通信
- `shutil.rmtree` - ディレクトリ削除
- `__import__` - 動的インポート

**プライバシーパターン（エラーレベル）**
- APIキー（OpenAI, GitHub, AWS, Slack等）
- ハードコードされたパスワード
- データベース接続文字列
- 秘密鍵

**プライバシーパターン（警告レベル）**
- ユーザーホームパス（`/home/username/`, `C:\Users\username\`）
- メールアドレス
- トークン/シークレット変数

#### 現在の対応状況

✅ **対応済み** - `scan_blend.py` で以下のスキャナーを実装：
- MalwareScanner
- PrivacyScanner
- BanditScanner（静的解析）

### USD (.usd / .usda / .usdc)

**リスクレベル: 高**

Pixarが開発したUniversal Scene Description。映像業界で急速に普及中。

#### コード実行リスク

| 機能 | 説明 | リスク |
|------|------|--------|
| Python式 | アトリビュート値にPython式を埋め込み可能 | 高 |
| カスタムスキーマ | 独自スキーマでコード参照可能 | 中 |
| アセット参照 | `@reference` で外部USDファイルを参照 | 中 |
| Payload | 遅延読み込みアセット参照 | 中 |

#### ファイル形式

- `.usd` - バイナリまたはASCII（自動判別）
- `.usda` - ASCII形式（テキスト解析可能）
- `.usdc` - バイナリ形式（Crate形式）
- `.usdz` - ZIP圧縮アーカイブ

#### 検出すべきパターン

```python
# Python式の埋め込み例
float xformOp:rotateX.timeSamples = {
    1: "python: math.sin(frame * 0.1) * 45"
}
```

- `python:` プレフィックスを持つ値
- 外部参照パス（パストラバーサルチェック）
- 絶対パス参照

#### 現在の対応状況

❌ **未対応** - 新規実装が必要

#### 実装優先度: 高

映像業界での普及を考慮し、優先的に対応すべき。

## 中リスク形式

### X3D / VRML (.x3d / .wrl)

**リスクレベル: 中**

Web3D標準形式。ECMAScriptによるスクリプト機能を持つ。

#### コード実行リスク

| 機能 | 説明 | リスク |
|------|------|--------|
| Script ノード | ECMAScript/VRML Scriptを埋め込み | 中 |
| EXTERNPROTO | 外部プロトタイプ定義の参照 | 低 |
| URLフィールド | 外部リソースの読み込み | 低 |

#### 検出すべきパターン

```xml
<!-- X3D Script ノードの例 -->
<Script DEF="MyScript">
  <field name="trigger" type="SFBool" accessType="inputOnly"/>
  <![CDATA[
    ecmascript:
    function trigger(value) {
      // 任意のJavaScriptコード
    }
  ]]>
</Script>
```

```vrml
# VRML Script ノードの例
DEF MyScript Script {
  url "javascript:
    function initialize() {
      // 任意のJavaScriptコード
    }
  "
}
```

#### 現在の対応状況

❌ **未対応** - 新規実装を検討

#### 実装優先度: 中

使用頻度は低下傾向だが、レガシーファイルの検査用に対応を検討。

### SVG (.svg)

**リスクレベル: 中**（一般用途）/ **低**（Blender用途）

2Dベクターグラフィック形式。BlenderではGrease Pencilのインポートに使用。

#### コード実行リスク

| 機能 | 説明 | リスク |
|------|------|--------|
| `<script>` タグ | JavaScript埋め込み | 高 |
| イベントハンドラ | `onload`, `onclick` 等 | 高 |
| 外部参照 | `xlink:href` による外部リソース | 中 |

#### Blenderでの扱い

Blenderのインポーターはスクリプトを**無視**するため、Blender用途では低リスク。ただし、SVGファイルを他のアプリケーション（ブラウザ等）で開く場合はリスクあり。

#### 検出すべきパターン

```xml
<svg xmlns="http://www.w3.org/2000/svg">
  <script type="text/javascript">
    // 任意のJavaScriptコード
  </script>
  <rect onload="maliciousFunction()" />
</svg>
```

#### 現在の対応状況

❌ **未対応** - Blender用途では優先度低

#### 実装優先度: 低

Blenderでの使用に限定すればリスクは低い。

---

### FBX (.fbx)

**リスクレベル: 低〜中**

Autodesk独自形式。業界標準の交換フォーマット。

#### プライバシーリスク

| 情報 | 説明 | リスク |
|------|------|--------|
| 作成者情報 | Creator, Author メタデータ | 中 |
| ファイルパス | 元のファイルパス情報 | 中 |
| ソフトウェア情報 | 作成ソフトウェア名とバージョン | 低 |
| タイムスタンプ | 作成・更新日時 | 低 |

#### コード実行リスク

FBX仕様自体にはスクリプト機能はない。ただし：
- 一部のDCCツールがカスタムプロパティとしてスクリプトを保存する可能性
- 外部テクスチャ参照によるパストラバーサル

#### 検出すべきパターン

- ユーザーホームパスを含むファイルパス
- 絶対パス参照
- カスタムプロパティ内のコード様文字列

#### 現在の対応状況

❌ **未対応** - プライバシースキャナーの実装を検討

#### 実装優先度: 中

公開配布するアセットではプライバシー情報の検査が有用。

---

### Collada (.dae)

**リスクレベル: 低**

XML ベースの交換フォーマット。

#### プライバシーリスク

| 情報 | 説明 | リスク |
|------|------|--------|
| `<author>` | 作成者名 | 中 |
| `<authoring_tool>` | 使用ソフトウェア | 低 |
| `<created>` / `<modified>` | タイムスタンプ | 低 |
| `<extra>` | カスタムデータ | 低 |

#### コード実行リスク

Collada仕様にはスクリプト機能はない。XMLベースのため、以下に注意：
- 外部エンティティ参照（XXE攻撃）
- `<extra>` 要素内のカスタムデータ

#### 現在の対応状況

❌ **未対応** - プライバシースキャナーの実装を検討

#### 実装優先度: 中

---

## 低リスク形式

### glTF (.gltf / .glb)

**リスクレベル: 低**

「3DのJPEG」と呼ばれる軽量交換フォーマット。

#### 特徴

- 設計上スクリプト実行機能を持たない
- JSON + バイナリバッファの構成
- 拡張機能（`KHR_*`, `EXT_*`）はデータ拡張のみ

#### 潜在リスク

| リスク | 説明 | 深刻度 |
|--------|------|--------|
| パストラバーサル | 外部バッファ/テクスチャ参照 | 低 |
| DoS | 巨大バッファによるメモリ枯渇 | 低 |

#### 現在の対応状況

❌ **未対応** - パス検証のみ検討

#### 実装優先度: 低

---

### DXF (.dxf)

**リスクレベル: 低**

CAD交換フォーマット。

#### プライバシーリスク

- ヘッダーセクションに作成者情報
- 図面パス情報

#### 現在の対応状況

❌ **未対応**

#### 実装優先度: 低

---

## 最低リスク形式（検査不要）

以下の形式は純粋なジオメトリ/アニメーションデータのみを含み、セキュリティスキャンは不要です。

| 形式 | 拡張子 | 用途 |
|------|--------|------|
| OBJ | .obj | メッシュデータ |
| PLY | .ply | 点群/スキャンデータ |
| STL | .stl | 3Dプリント用メッシュ |
| Alembic | .abc | アニメーションキャッシュ |
| BVH | .bvh | モーションキャプチャデータ |
| 3DS | .3ds | 3ds Max旧形式メッシュ |

## 実装計画

### フェーズ1: 高優先度

| 対象 | スキャナー | 説明 |
|------|-----------|------|
| USD | UsdScriptScanner | Python式、外部参照の検出 |
| USD | UsdPrivacyScanner | パス情報の検出 |

### フェーズ2: 中優先度

| 対象 | スキャナー | 説明 |
|------|-----------|------|
| FBX | FbxPrivacyScanner | メタデータからの個人情報検出 |
| Collada | ColladaPrivacyScanner | XML解析による情報検出 |
| X3D/VRML | X3dScriptScanner | Scriptノードの検出 |

### フェーズ3: 低優先度

| 対象 | スキャナー | 説明 |
|------|-----------|------|
| glTF | PathTraversalScanner | 外部参照パスの検証 |
| SVG | SvgScriptScanner | スクリプト検出（Blender外用途） |
| DXF | DxfPrivacyScanner | ヘッダー情報の検出 |

### 共通コンポーネント

| コンポーネント | 説明 |
|----------------|------|
| PathValidator | パストラバーサル検出の共通ロジック |
| MetadataExtractor | 各形式からのメタデータ抽出基盤 |
